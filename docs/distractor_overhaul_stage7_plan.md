# Distractor Overhaul, Stage 7: Snapshot Export

Execute task by task, in order. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the two-directory `eval-set` export with a dated, standalone, fully documented snapshot: one directory `snapshot_<YYYYMMDD>/` under `../evaluation_data/`, holding four halves rendered in one run from identical ground truth (`plain_`, `distractor_`, `labelled_varied_`, and `degraded_`, the distractor receipts at three severity tiers), scored-field geometry for the three clean halves, a `MANIFEST.json` recording the date, the generator commit, input hashes and every file's SHA-256, a README written for a reader with no repository access, and a `tools/` directory whose `verify_snapshot.py` runs on the standard library alone. Projects that consume the corpus on PROD never run the generator; the project owner uploads the snapshot to S3 by hand (out of scope). Exit criterion: one flipped byte fails `verify_snapshot.py`; a dirty tree is refused; a missing root fails fast.

**Architecture:** Task 1 rewrites the export. A new package, `generators/snapshot/`, resolves `eval_set.output_root`, reads the repository state (refusing tracked changes), runs the cheap entry and layout checks, then renders every case three times (plain, distractor, labelled varied) and degrades each distractor receipt once per tier, checking every render as `validate` does (density bounds on the distractor and labelled varied renders, the drawn-field guard on the plain and labelled varied renders, the unambiguity rules inside the labelled varied render). Everything is written into a staging directory beside the destination and renamed into place only once every check has passed and the repository state is unchanged, so a refused or interrupted export leaves no partial snapshot behind, and an earlier snapshot of the same name is replaced only by a complete one. The projection helpers in `generators/eval_set.py` (`project_fields`, `write_jsonl`, `csv_from_jsonl`) are reused unchanged, so the ground-truth files keep their pinned format. Task 2 adds what makes the directory standalone: the manifest, a `SHA256SUMS` file, the generated README, the three tools, and the documentation, and closes the stage with the full suite and the first real snapshot.

**Tech Stack:** Python 3.12, Pillow 12.2.0, PyYAML, Typer, the layout DSL, the distractor, overlay and label packages, Augraphy and OpenCV (degradation), `hashlib`, `subprocess` (git), pytest, conda env `synthetic`.

**Spec:** `docs/distractor_overhaul_design.md` sections 3 (degraded half from the distractor receipts), 6 (the sidecar, and the 8 October revision: per-type sidecars assembled at export), 9 (checks on every render, plain renders reported but never bounded), 10 (the invoice fixes the change notes record), 11 (snapshot layout, `MANIFEST.json`, README, `eval_set.output_root`, `--out` removed, dirty tree refused), 12 (snapshot tests) and 13 (stage 7). The Stage 7 roadmap row of `docs/distractor_overhaul_plan.md` and the Stage 7 constraints recorded in the outcomes of Stage 0, `docs/distractor_overhaul_stage3_plan.md` through `docs/distractor_overhaul_stage6_plan.md` are binding. Where the spec is silent or disagrees with the code, the Decisions below rule.

## Global Constraints

- Conda env `synthetic`; run every tool as `conda run -n synthetic <command>` from the repository root.
- YAML is the single source of truth: the output root, the snapshot and half prefixes, the geometry directory name and the README's field descriptions are required YAML keys. Python holds no defaults for them. File names fixed by the spec (`MANIFEST.json`, `README.md`, `SHA256SUMS`, `tools/`, the `%Y%m%d` stamp) are contract constants, as `_DATE_FORMAT` already is.
- Every fail-fast error names What, Where (absolute file path and dotted key, or the command line), Expected (with an example) and Recover, on lines starting with those labels; tests assert this with `assert_diagnostic_error`.
- Nothing a snapshot contains is written inside the repository; test output goes to `tmp_path`. The export never reads the ABN register, and nothing outside the spec's layout ships.
- No render changes: the plain, distractor, labelled varied, derived and eval-format pins pass with no re-bless. Ground truth, links and selections are untouched (no reseed).
- No TFN anywhere: the corpus has none, and no snapshot file may carry a TFN-shaped field, key or label.
- No real business or brand names, and no value copied from `ground_truth/`, in code, tests, the README template or prose; example values are invented and checked absent from `ground_truth/`.
- Line length 108; Python 3.12 types; `pathlib.Path`; Google-style docstrings; `raise ... from err` in `except` blocks.
- `tests/` is tracked in git since 8 October 2026: test changes are committed with their task. Per-task gate: `conda run -n synthetic pytest tests/ -m "not slow"` plus the slow tests named in the task, `ruff check --fix --ignore ARG001,ARG002,F841 *.py`, `ruff format --check generators scripts linking tests *.py`, `mypy . --ignore-missing-imports`, `python -m generators.pipeline validate`. The full suite (about 2.5 hours) runs once, at the end of Task 2. New slow tests are limited to the two named below. One review per task; review fixes are applied without a second review. Commit messages carry no trailers.
- Prose uses British spelling and no em-dashes; no tooling references in tracked files.

## Decisions

Numbered so reviews can cite them. Each records where the spec is silent or disagrees with the code, and why.

1. **The heavy tier is not bit-reproducible, and the snapshot says so rather than fixing it.** Augraphy's `Folding` draws its fold noise from numba's per-thread generator inside a parallel loop, which no Python-level seed reaches (Stage 0 carry; pinned by the strict expected failures in `tests/degradation/test_augment.py` and `test_camera.py`, which stay as they are). By the project owner's ruling there is no fix and no investigation in this stage. The snapshot hashes exactly the files produced; the README states plainly that regenerating the `_v3` (heavy) receipts from the same commit gives different pixels, while the light (`_v1`) and moderate (`_v2`) tiers and all three clean halves regenerate byte-identically (as the existing determinism tests show for the tiers without a fold); and `verify_snapshot.py` checks a snapshot against its own manifest, never against a regeneration. Comparability therefore rests on the manifest (Decision 9), not on re-running the generator.
2. **`eval-set` becomes the snapshot export; `--out` and `--force` are removed.** The command keeps its name (and the hidden `eval_set` alias) and takes only `--config`. The destination is `<eval_set.output_root>/<snapshot_dir_prefix>_<YYYYMMDD>/`. An existing snapshot directory of that name is replaced (revised 8 October 2026 by the project owner's ruling, which overrides the earlier refusal): the export builds into its staging directory as before and, once every check has passed and the repository state is unchanged, removes the earlier snapshot and renames the staging directory into place. A leftover staging directory from a failed run is cleared at the start. There is no refusal and no flag. `export_eval_set` and `_prepare_dir` are deleted; nothing else calls them.
3. **`eval_set.output_root` resolves like the working directories, but must already exist.** Resolved against the repository root; refused four-part when the key is missing or not a string, when it resolves inside the repository, or when it is not an existing directory. Where `<abs>/config/generation_config.yml -> eval_set.output_root`; Expected `output_root: ../evaluation_data`; Recover 'create the directory beside the repository, or correct eval_set.output_root'. The superseded keys `clean_dir_prefix` and `degraded_dir_prefix` are refused if present (What names the replacement), so a stale config cannot look meaningful.
4. **A dirty tree means tracked changes; it is checked at the start and again before publishing.** `git status --porcelain --untracked-files=no` must be empty and `git rev-parse HEAD` must succeed; untracked files are not refused, since the code and YAML the export reads are tracked and an untracked file affects nothing unless a tracked one names it. The state is read again after rendering, and a changed HEAD or a newly dirty tree discards the staging directory, because a manifest naming a commit that did not produce the files is worse than none. Git missing or no repository is refused four-part. The repository state is an injectable argument of the export function so tests run from a working tree under development; the command always reads the real one.
5. **Every half is rendered fresh by the export; nothing is read from `<output_dir>`.** The spec's Stage 6 revision has the export assemble the sidecars `generate` writes, but those carry `{case}_{layout}` filenames and may be stale relative to HEAD. The export renders all four halves in one process from the committed tree and builds the sidecar rows with the existing `sidecar_row`, under the generic filename.
6. **Halves are flat and paired by filename; the labelled_varied half has one sidecar.** Each half holds its images directly, named `{case}_{doc_type}.png` as today (no layout in a filename). The three clean halves share filenames and byte-identical `ground_truth.csv` and `.jsonl`; degraded images keep their tier suffix and their own receipt-only ground truth, as today. The design's half carries a single `label_styles.jsonl` at its root (rows sorted by `image_file`, the Stage 6 per-type rows merged; bank rows carry `styles: {}`), which resolves Stage 6's "per-type sidecars" against section 11's single file. It is metadata, never ground truth: no extraction file gains a column from it.
7. **The degraded half degrades the distractor receipts.** Spec section 3 rules; the current export degrades the plain render. Seeds are unchanged (`tier_seed(degradation_seed, index)`).
8. **Checks on every render, collected, then refused as one.** Before rendering: `validate_entry`, the bank ledger check, the distractor value check and `validate_layout` per layout. During: a `DensityCheck` on every distractor and labelled varied render, the drawn-field guard on every plain and labelled varied render (the pairing `validate` uses), the overlay and unambiguity checks inside the renderers. Every failure is collected; any failure refuses the export with a four-part summary listing each check's own diagnostic, and nothing is published. Plain renders are measured and reported in the manifest, never bounded. The full `validate` is not repeated (it would draw every page again); the runbook makes it the step before the export.
9. **The manifest covers inputs, not just outputs.** `config_sha256` holds every tracked file under `config/` plus `environment.yml`; `ground_truth_sha256` every tracked file under `ground_truth/`; `versions` records Python, Pillow, NumPy, OpenCV and Augraphy. `counts` gives each half's total and per document type; `label_style_counts` and `label_refusal_counts` come from the sidecar rows, per document type then field; `metrics` gives min, median and max of the scored-ink ratio, distractor share and page fill per render then document type. `files` maps every file except `MANIFEST.json` and `SHA256SUMS` to its SHA-256, by POSIX path relative to the snapshot root. No absolute or home path appears in any snapshot file. `dirty` is written as `false`, as the spec shows, since a dirty tree never gets this far.
10. **`SHA256SUMS` makes the spec's `shasum -a 256 -c` command real.** That command needs a checksum file; the manifest is JSON. The export writes `SHA256SUMS` (`<hash>  <path>` lines, sorted) from the same map, and `verify_snapshot.py` checks the two agree. The manifest cannot vouch for itself, so the export prints `MANIFEST.json`'s own SHA-256 for the owner to record beside the upload, and the README says so.
11. **`verify_snapshot.py` is stdlib-only and strict.** Lives at `scripts/verify_snapshot.py`, copied byte-for-byte into `tools/`. Run as `python tools/verify_snapshot.py [snapshot_dir]` (default: the parent of `tools/`). It fails, exit 1, on a missing, changed or extra file, a manifest entry that is absolute or climbs out with `..`, a `SHA256SUMS` that disagrees with the manifest, or a count that disagrees with the files present; it names each offending path (up to a cap, with the total). The one tolerated extra is `.DS_Store`, reported as a note. A notebook run that writes `figures/` inside the snapshot is an extra and fails, which is correct.
12. **Tools ship as reviewed copies.** `check_extractions_match_gt.py` ships, so this stage gives it the tests Stage 0 found missing and brings it into line: its diagnostics use the `Recover:` label, its success line loses its dash, and its hint no longer cites `--out`. `score_extractions.ipynb` ships with outputs cleared and every `execution_count` set to `null`, so no earlier run's numbers read as this snapshot's.
13. **Field descriptions live with the extraction contract.** The README defines all 17 fields; the text is a required `field_descriptions:` block in `config/extraction_schema.yml`, one entry per field named under `document_fields`, refused four-part when a field lacks one or one names no field. `eval_projection` and `scripts/generate_extraction_gt.py` ignore the new key (tested).
14. **"Changes since the previous snapshot" tolerates the rebuilt history.** The export finds the latest earlier `snapshot_*/MANIFEST.json` under the root. If its commit is an ancestor of HEAD, the section lists the commit subjects between them; if it is unknown to the repository (history rebuilt on 8 October 2026), the section says so; with no earlier manifest, it says this is the first manifested snapshot. Every README also carries the fixed comparability notes: `synthetic_` is renamed `plain_`; the section 10 invoice fixes; and no score from an export before this snapshot is comparable, because bank statements, receipt unit prices and one bank layout's closing balance changed in Stage 5, and every receipt and invoice changed with the ABN-register reseed.
15. **Only the spec's layout ships.** The export writes an allow-list: the four halves, `geometry/` (`plain.jsonl`, `distractor.jsonl`, `labelled_varied.jsonl`, scored boxes only, generic filenames, as `generate` writes them), `tools/` (three files), `README.md`, `MANIFEST.json`, `SHA256SUMS`. Transaction links, derived benchmark views and the ABN register are not part of it.

## Review Focus

1. **A manifest that does not describe what was produced:** a dirty tree, a commit made or a file edited while rendering, a hash computed before a file's last write, or `SHA256SUMS` built from a different map. Tests: a fake state that changes between start and publish leaves no snapshot and no staging directory; a real temporary git repository with a modified tracked file is refused four-part; every manifest hash is recomputed from disk and matches. Tasks 1 and 2.
2. **Halves that do not pair:** differing filenames, a ground-truth file differing between clean halves, a sidecar row for a missing image, a degraded receipt made from the plain render. Tests: the three clean halves have equal filename sets and byte-identical ground truth; the sidecar holds exactly one row per labelled varied image; a light and a moderate degraded image equal `degrade_receipt` of the distractor render (bytes), and differ from the plain render's (the heavy tier cannot be compared, Decision 1). Task 1.
3. **A check skipped on a shipped render:** density or the drawn-field guard run on one mode only, or a failure logged and published anyway. Tests: a density bound tightened in a scratch `config/distractors.yml` refuses the export four-part with nothing published; a drawn-field failure forced on a labelled varied render does likewise; plain renders out of bounds are reported in `metrics` and not refused. Task 1.
4. **Verification that passes when it should not.** Tests on a small exported snapshot copied to `tmp_path`: one flipped byte in an image (the exit criterion), a missing file, an extra file, a tampered `SHA256SUMS`, an edited count, a manifest path with `..`: each exits 1 naming the path; the untouched copy exits 0; `verify_snapshot.py` imports only standard-library modules (checked from its AST against `sys.stdlib_module_names`) and runs under a bare interpreter in a subprocess. Task 2.
5. **Something leaking into a snapshot:** the ABN register, a local absolute path, a TFN-shaped key, a layout name in a filename, a `LABEL_` key or style column in ground truth, a distractor box in geometry, a notebook's old outputs, a file written inside the repository. Tests: the file set equals the allow-list exactly; no text file contains the home directory, the repository path, `abn_register` or `.npy`; no key or text matches `tfn` or `tax file` (case-folded); ground-truth columns equal the schema's; every geometry box is scored; the export succeeds with the register loader patched to raise; `git status --porcelain` is unchanged by an export. Tasks 1 and 2.
