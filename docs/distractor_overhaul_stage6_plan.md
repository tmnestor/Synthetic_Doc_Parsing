# Distractor Overhaul, Stage 6: Label Variation

Execute task by task, in order. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third clean render, `labelled_varied`: the distractor render of every case, with the same ground truth, the same distractor selection and the same overlay, except that the labels of BUSINESS_ABN, GST_AMOUNT and TOTAL_AMOUNT are each drawn, per case, as `labelled` (today's wording), `variant` (a realistic alternative wording) or `unlabelled`. An unambiguity validator refuses any choice that would leave a careful reader unable to identify the field, and the selector then redraws under a policy declared in YAML, recording every refusal. Each case's choices go to a `label_styles.jsonl` sidecar, never to the extraction ground truth. Exit criterion: each unambiguity rule has a failing fixture.

**Architecture:** Task 1 routes the three labels through label sites with no visible change: a `label_styles` field provider emits one `{LABEL_*}` key per site, every receipt and invoice layout binds its ABN, GST and total labels through those keys, the totals of every such layout are wrapped in a `region: totals` stack, and the recorder learns what each ink line says (its text, size and weight), which label each site drew and where the totals region lies. With no choice supplied the provider emits today's wording, so plain and distractor renders stay byte-identical. Task 2 adds the selection (per-case style and wording orders on their own seed domain), the unambiguity validator and the render loop that refuses and redraws, and checks every `labelled_varied` render in `validate` with the drawn-field guard, the density bounds and the validator. Task 3 adds `generate --distractors --label-variation`, the sidecar, the `labelled_varied` pixel snapshot and the documentation, and closes the stage with the full suite.

**Tech Stack:** Python 3.12, Pillow 12.2.0, PyYAML, Typer, the layout DSL, the distractor package, the overlay package, pytest, conda env `synthetic`.

**Spec:** `docs/distractor_overhaul_design.md` sections 3 (label presence), 4 (label-varied render, `LABEL_VARIATION`), 6 (label variation: styles, `{LABEL_*}` bindings, sidecar, unambiguity rules), 8 (style weights and wording in `config/distractors.yml`), 9 (check 4, label unambiguity; check 5, density on `labelled_varied` renders), 11 (the `labelled_varied_` half and its sidecar; built in Stage 7), 12 (label tests) and 13 (stage 6). The outcome sections of `docs/distractor_overhaul_plan.md` (Stage 0), `docs/distractor_overhaul_stage3_plan.md` and `docs/distractor_overhaul_stage4_plan.md` are binding, as are the Stage 5 rulings recorded with its plan (the drawn-field guard and its `drawn_value_policy`, `geometry_exemptions`, the overlay, the four hands). Where the spec is silent or disagrees with the code, the Decisions below rule.

## Decisions

Numbered so reviews can cite them. Each records where the spec is silent or disagrees with the code, and why.

1. **Bank statements carry no label sites.** The spec varies BUSINESS_ABN, GST_AMOUNT and TOTAL_AMOUNT, which no bank layout prints, and section 13 binds `{LABEL_*}` in receipt and invoice layouts only. `label_variation.doc_types.bank_statement` is an explicit `[]`, no bank layout declares `label_styles`, and the bank `labelled_varied` render is byte-identical to its distractor render (tested), so the half still holds 165 images under shared filenames. Bank sidecar rows carry `styles: {}`.
2. **Today's label lives in the layout, the alternatives in `config/distractors.yml`.** Today's wording differs by site (receipts `GST`, the separate invoice totals `GST (10%)`, the inclusive invoice totals `GST included (10%)`), so a provider cannot know it. Each layout's `label_styles` entry declares, per field, `labelled:` (the exact wording printed today) and `pool:` (the name of a wording pool in `label_variation.pools`). With no choice supplied the provider emits `labelled`, which is what makes the other two renders unchanged.
3. **A label site's wording carries its own punctuation; the block's separator becomes empty.** The pair primitive draws `label + separator`, so an empty label would still print a lone `:` before an unlabelled value. Every label-site pair moves its separator into the labelled wording (`Total:` with `separator: ""`), which draws the same string and so the same pixels; every pool wording then carries its own punctuation (`Amount due:`, `Includes GST of`) and an unlabelled site prints the value alone. A pair whose label interpolates to the empty string draws and records nothing for the label. Text sites (`content: "{LABEL_BUSINESS_ABN}{BUSINESS_ABN}"`) carry the separating space in the wording (`ABN: `), so the wording of a text site must end in whitespace or be empty (validated).
4. **The value's box still holds the value alone.** `binding.bound_label` today finds a label only when the template's sole placeholder is the bound field at its end; `{LABEL_BUSINESS_ABN}{BUSINESS_ABN}` has two placeholders. It is extended: when every other placeholder in the template is a `LABEL_` key and the bound field ends it, everything before the field is the label. The guard's 'ABN box holds the value alone' test runs for every style.
5. **The selection lives outside the provider; the provider only maps a choice to keys.** Refusal needs a rendered page, so selection and redraw sit in a render loop (`generators/labels/render.py`) that passes a `LabelChoice` down through the renderer to `apply_field_providers`. `label_styles` is registered as a third provider kind (`labels=True`), called as `provider(entry, params, *, choice)`; it emits only `LABEL_` keys (registration refuses any other key and any scored column, as the existing registry does). A render whose `labels` argument is `None` is a plain or distractor render; a renderer given a choice without `distractors=True` refuses it four-part (the spec layers `LABEL_VARIATION` on `DISTRACTORS`). The renderer keyword defaults to `None`, an API default rather than configuration, so the hundreds of existing call sites are unchanged.
6. **One seed per case, drawn as orders, so a redraw moves nothing else.** Each case draws from `sha256("{case_id}:labels:{doc_type}")`, the spec's domain, independent of the `distractor`, `overlay` and `pos` digests. For each varied field, in the YAML order of `label_variation.doc_types.<type>`, the stream yields a weighted ordering of the three styles (draw by weight, remove, repeat) and a shuffled ordering of the site's pool. The choice is the first style in the order, and for `variant` the first wording; a refusal moves that field to its next wording, then its next style. Nothing is drawn after the orders, so a redraw of one field never shifts another field's draws, and `labelled` always terminates the order.
7. **`labelled` is never refused.** It is exactly the distractor render's label, already validated in Stage 5, so the unambiguity rules apply to `unlabelled` and the collision and overlap rules to `variant`. A field whose order reaches `labelled` therefore always renders, and the loop needs no exhaustion error.
8. **Refusal policy is a YAML enum.** `label_variation.refusal_policy: redraw` (shipped) or `fail`. Under `redraw` each refusal is recorded (field, style, wording, rule, evidence) in the render's outcome, the sidecar and the generate summary, and the next candidate is drawn. Under `fail` the first refusal raises the four-part diagnostic; the per-rule fixtures run under `fail` to prove each message, and once under `redraw` to prove the fallback.
9. **The totals block is declared, not inferred.** Section 6 speaks of 'the totals block', which no layout names, and inferring it from line spacing fails on receipts (rules are not ink and every line shares one pitch). A `stack` may carry `region: totals` (the one region name, validated); a stack draws exactly what its children would draw in its place, so wrapping adds no pixel. The recorder records the region's box (the column's x extent, from the stack's start y to its end y). Every layout with a GST or total site has exactly one totals region, containing both sites (validated). Receipts wrap SUBTOTAL, GST, TOTAL and 'You saved'; invoices wrap the right-hand totals column (Subtotal, GST, Total, Amount paid, Balance due). The account summary panel and the remittance slip stay outside it.
10. **Ink records say what they drew.** The unambiguity rules read numbers, amounts, sizes and weights off the page, and `InkRecord` holds only a role, a box and a mark flag. It gains required `text`, `size` and `bold`: a text line records its drawn string, its font size and weight; a code mark records its encoded payload (size 0, regular), so a barcode's digits count as printed numbers; stamp words and handwriting record their text. Every `record_ink` call site passes all three. Density reads boxes only and is unchanged.
11. **'The figure sits above the total' stands, so an inclusive layout never prints GST unlabelled.** `tax_invoice_gst_inclusive` prints GST after the total, as a component of it; a bare figure below a bold total reads as a payment or balance line. The rule is kept as written: there the validator always refuses `unlabelled` GST and the selector redraws. The measured share is reported, and the per-style coverage test (Review Focus 5) counts invoices as a whole.
12. **'Shares its size or weight' is read as 'size and weight', page-wide, plus prominence within the region.** Taken literally, any near-miss amount drawn at the body size (every receipt line) would forbid an unlabelled total on every receipt carrying one, and section 12's fixture says 'size and weight'. The rule is therefore two checks: no distractor-role amount line anywhere on the page is drawn at the total's size and weight together, and within the totals region no other amount line is larger, or the same size and bold when the total is not.
13. **'Last amount' ignores repeats of the total.** A paid invoice prints 'Amount paid' (a `repeat` of TOTAL_AMOUNT) below the total; reading it as the total gives the right answer, so lines whose amount equals TOTAL_AMOUNT do not count against 'last'. Every other amount line below the total does: 'Balance due $0.00' (a near-miss, drawn with 'Amount paid') and 'You saved' refuse an unlabelled total, which is what a careful reader would struggle with.
14. **An 11-digit number is a maximal run of digits joined by single spaces with exactly 11 digits.** So `12 345 678 901`-style groupings count, a 16-digit transaction id does not, and a phone number (10 digits) does not. Runs are read from every ink line's text and every code mark's payload except the BUSINESS_ABN value line itself; a run is a rival when it passes the ABN checksum (`common.validate_abn`).
15. **A variant collides with any distractor line, not only near-miss labels.** Ink does not know an item's kind, and a wording sharing a word with any distractor on the page invites the same misreading. A variant is refused when its words, case-folded and stripped of punctuation, share any word outside `label_variation.collision.ignore_words` with any distractor-role text line on the page ('Balance' against 'Balance due', 'Amount due' against an account summary's 'Amount due'). Repeats and plain text lines (a table's 'Amount' header) do not collide.
16. **A variant may not crowd its neighbours or shrink its value.** A right-aligned pair pushes a long label left by `min_gap`, into the payment-details column; a text site fits label and value together, so a long wording would shrink the ABN. Two guards: at validate time every text-site wording, with a 14-character ABN-shaped string, fits its site's budget at the nominal size (a static four-part refusal names the wording, the site and the width); at render time a variant's label ink meeting any other ink box is refused (rule `overlap`) and redrawn. A forced test renders every wording on every site of every layout for every case.
17. **Variant pools are per site, not per field.** Receipts print upper-case labels and invoices title case, and a separate GST line and an inclusive GST note want different wordings. Pools are named for their site (`abn_receipt`, `abn_invoice`, `gst_receipt`, `gst_invoice_added`, `gst_invoice_included`, `total_receipt`, `total_invoice`). A pool wording that normalises to its site's own labelled wording is refused (it would be recorded as a variant while printing today's label), as are duplicates after normalisation. The spec's example list is the starting content: ABN as `A.B.N.`, `ABN No.` and `Australian Business Number`; GST as `Tax`, `GST 10%`, `GST incl.` and `Includes GST of`; total as `Amount`, `Total (inc GST)`, `Amount Due` and `Balance`, each adapted to its site's case and punctuation, and any wording the validator refuses on most pages is reported rather than kept silently.
18. **The value keeps its size and weight when its label goes.** The spec's 'large bold figure with no label' is today's total, already bold (and header-sized on invoices). No style changes a value's font, so the only difference a model sees is the label; an unlabelled ABN on a left-aligned or centred line moves left or recentres by the label's width, which is the one permitted change to a scored box (tested).
19. **Weights are per field and every style keeps positive weight.** `label_variation.fields.<FIELD>.weights: {labelled, variant, unlabelled}`, each greater than zero, starting equal. Task 2 measures the realised counts per field per document type after refusals and records them, dated, in the YAML comment. Weights are never tuned towards a score; they may be raised for `unlabelled` only to restore a style a document type would otherwise almost never show, with the reason written beside the change.
20. **Density applies to `labelled_varied` renders with the distractor bounds.** Section 9 enforces density on both. Removing labels removes unscored text, so the scored-ink ratio rises slightly. Task 2 measures all 110 receipt and invoice renders; the shipped bounds stay if every render meets them, and otherwise are re-set by the Stage 4 rule (at least 10% relative headroom over the corpus and the synthetic entries) with a dated comment, never moved without the measurement.
21. **The sidecar is written per type directory by `generate`.** `generate --type receipts` must not erase the other types' rows, so `generate --distractors --label-variation` writes `<output_dir>/<labelled_varied_output_subdir>/<type>/label_styles.jsonl`, one row per image. Stage 7 assembles the half's single `label_styles.jsonl`, its counts in `MANIFEST.json` and the README section; `eval-set` is untouched here.
22. **Carried items reviewed, not acted on.** Stage 4 asked for a review of scored-field type sizes beside label variation (PAYER_NAME on all invoice layouts and SUPPLIER_NAME on four print at the body size). Task 3 measures and reports each scored field's drawn size per invoice layout; sizes are not changed in this stage, because label presence is the one factor `labelled_varied` varies and a size change would re-bless every plain invoice for a separate question. Trade invoices listing materials before labour, and the Stage 5 carry-overs (ATM withdrawals annotated as claims, 12-character employer names, the stamp-jitter fallback breaker), are outside this stage.

## Review Focus

1. **A label change leaking into the control renders, or moving the distractors.** If any site's labelled wording differs from today's string (a lost separator, a changed case), or the provider runs differently with no choice, the plain or distractor pixels move. The plain, distractor and derived snapshots pass unchanged after every task; a forced all-`labelled` choice reproduces the distractor render's bytes for all 110 receipts and invoices; every `labelled_varied` render's `DX_` values and overlay marks equal the distractor render's. Tasks 1 and 2.
2. **An unlabelled field accepted while ambiguous**, because a draw path records no ink text (a table cell, a fitted wrapped line, a barcode caption), the region is wrong, or an amount is misread. A test asserts every text ink record in every distractor render carries a non-empty `text` and a positive `size`; each rule has a unit fixture on synthetic geometry and the spec's two (a second checksum-valid ABN beside an unlabelled one, a near-miss sharing an unlabelled total's size and weight) also an end-to-end rendered fixture, all failing under `fail`. Task 2.
3. **A scored value no longer verbatim, or its box swallowing a label.** The `{LABEL_*}` placeholder before a bound field must still be excluded from the value's box and string (Decision 4). The drawn-field guard runs on all 110 `labelled_varied` renders and on every forced style; for every style, the BUSINESS_ABN box's drawn string is the ground-truth ABN alone, and every other scored box is identical to the distractor render's. Tasks 1 and 2.
4. **A variant colliding with a distractor or crowding its neighbours**: 'Balance' on a page with 'Balance due', 'Amount due' beside an account summary, a long inclusive GST label pushed into the payment details. Fixtures for `collision` and `overlap` fail under `fail`; the forced every-wording test asserts no accepted variant shares a word with a distractor line or meets another ink box on any case and layout. Task 2.
5. **Silent refusal or a skewed distribution**: a redraw that always lands on `labelled`, so a document type never shows `unlabelled` for a field, or a sidecar that disagrees with the page. Tests: every style occurs for every varied field in each of receipts and invoices; the sidecar's style and wording for every image equal the label each site recorded at draw time; every refusal appears in the sidecar and the summary count; under `fail` the first refusal raises. Tasks 2 and 3.

### Task 2: Selection, the unambiguity validator and redraw

**Files:** `generators/labels/select.py`, `generators/labels/unambiguity.py`, `generators/labels/render.py` (new); `generators/overflow_check.py` (a `labelled varied` mode); `generators/pipeline.py` (`validate` runs it); `config/distractors.yml` (pools tuned, weights measured, density comment if re-measured); local tests and fixtures.

Interfaces:
- `draw_label_orders(case_id, doc_type, sites, config) -> dict[str, list[LabelPick]]`: per varied field, the full candidate order (Decision 6), ending in `labelled`.
- `check_label_choice(geometry, choice, entry, *, case_id, layout_id, doc_type, config, policy) -> list[Refusal]`, where `Refusal(field, style, wording, rule, evidence)` and `rule` is one of `abn_rival`, `gst_outside_totals`, `gst_below_total`, `gst_rival`, `total_not_last`, `total_not_prominent`, `total_near_miss_twin`, `collision`, `overlap`. `geometry` is the renderer's `geometry_out` (boxes, texts, ink, labels, regions); `entry` the provider-enriched entry (`entry_out`).
- `render_labelled_varied(renderer, entry, layout, *, doc_type, config, geometry_out=None, ink_out=None) -> tuple[Image.Image, LabelOutcome]`: renders with the first candidates, checks, and on a refusal advances that field's order and re-renders, until accepted; `LabelOutcome(choice, refusals)`. Under `refusal_policy: fail` the first refusal raises `LabelRefusalError`.

Rules (each refusal names case, layout, field, style, wording and the evidence):
- `abn_rival` (unlabelled ABN): another 11-digit run on the page passes the checksum (Decision 14); evidence is the run, its line text and box.
- `gst_outside_totals`, `gst_below_total`, `gst_rival` (unlabelled GST): the value line is not inside the totals region; it is not above the total's value line; another amount line in the region equals TOTAL_AMOUNT / 11 rounded half-up to cents.
- `total_not_last`, `total_not_prominent`, `total_near_miss_twin` (unlabelled total): an amount line other than a repeat of the total lies below it in the region (Decision 13); another amount line in the region is larger, or as large and bold where the total is regular; a distractor-role amount line anywhere on the page has the total's size and weight (Decision 12).
- `collision` (variant): the wording shares a non-ignored word with a distractor-role text line (Decision 15).
- `overlap` (variant): the label's ink box meets another ink box (Decision 16).
- Amount lines are ink lines whose text holds a money token read under `drawn_value_policy` (currency sign, grouping), so the validator and the guard read amounts one way.

### How the shipped code differs from this plan's text

- **Rule fixes after review.** Rival ABNs are read as sliding 11-digit windows over digit groups, so a longer reference number cannot hide one; an unlabelled value whose line moves onto neighbouring ink is refused as an overlap; `ignore_words` is per field; only the refused field advances to its next candidate. `totals_region_fields` is a required YAML key rather than a Python constant.
- **Wordings.** `label_variation.withheld_by_state` withholds 'Balance:' from a paid invoice's total. The receipt GST pool dropped 'INCLUDES GST OF' and 'GST INCL.', because every receipt prints GST as a line added between subtotal and total. 'A.B.N.' is refused under Decision 17, so receipts offer 'ABN NO. ' and 'ABN NUMBER: '. The account summary's 'Amount due' repeats the total and is treated as a repeat, not a rival.
- **Realised styles** (labelled / variant / unlabelled, all 55 cases per type, recorded with refusal counts in `config/distractors.yml`): receipts ABN 20/17/18, GST 20/18/17, total 21/20/14; invoices ABN 22/20/13, GST 19/21/15, total 23/18/14. Each label is absent on about 28% of receipt and invoice pages. Unlabelled pages are selected by content (the GST-inclusive invoice layout never drops GST or the total; no receipt with 'You saved' below its total drops the total), so the experiment compares each case's distractor and labelled_varied renders rather than styles within one render. Invoice total variants mostly keep the word 'Total'.
- **Bank statements** carry no label sites; their labelled_varied pages are byte-identical to their distractor pages.
- **Type sizes (Stage 4 carry):** PAYER_NAME prints at 20 on all eight invoice layouts and SUPPLIER_NAME at 20 on four, below the 28 body size; reported, not changed.
